# CleanFixHarish public mobile, performance, and media repair

Execute this brief in the current workspace. Review every existing uncommitted change first; keep, improve, or replace it. Do not touch unrelated untracked documents. Do not commit, push, or deploy.

## Reported production failures

- The public site can render on Android as a zoomed-out desktop canvas that requires pinch zoom, while `/admin` is responsive.
- The website and installed application load and react too slowly.
- Public pages need a coherent set of explanatory CleanFixHarish documentary photos instead of weak or generic visuals.

## Required mobile coverage

- Test 320, 360, 390, and 412 CSS-pixel portrait widths plus phone landscape.
- Reproduce Android Chrome `Desktop site` behavior with a coarse pointer and a virtual viewport around 980px.
- Cover Hebrew RTL and English LTR.
- Audit every public route: `/`, `/services`, `/quote`, `/account`, `/partners`, `/about`, `/how-it-works`, and `/why-trust-us`.
- No horizontal scrolling, fixed desktop canvas, tiny multi-column desktop grids, clipped content, unsafe fixed controls, or undersized touch targets.
- Preserve browser zoom and accessibility. Never add `user-scalable=no` or `maximum-scale=1`.

## Performance requirements

- Profile the production build and identify the largest initial-load costs.
- Reduce initial JS/CSS/media work through safe route-level lazy loading, code splitting, responsive image sources, dimensions/aspect ratios, and below-fold lazy loading.
- Keep the home-page LCP image eager/high-priority but do not eagerly load below-fold documentary images.
- Ensure public API calls do not block first paint and do not cause layout shifts.
- Avoid duplicate font/image downloads and unnecessary animation on mobile/reduced-motion devices.
- Keep installed-PWA update behavior deterministic and prevent an old HTML/app shell from remaining cached.
- Set correct cache headers: HTML must revalidate or not be stored, `sw.js` must revalidate, fingerprinted assets may be immutable.

## Media integration

New optimized documentary photos will be placed under `app/frontend/public/assets/images/cleanfix-mobile-v3/`. Build the public components so those assets can be inserted consistently across service cards and explanatory sections using responsive `<picture>`/`srcset`, explicit aspect ratios, useful bilingual-context alt text, lazy loading below the fold, and no cumulative layout shift. Do not invent testimonials, certifications, uniforms, logos, or unsafe trade work.
