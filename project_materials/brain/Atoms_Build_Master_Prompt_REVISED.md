# CleanFixHarish — Revised Atoms AI Master Prompt

> This revision preserves the original Perplexity brief while applying the approved
> CleanFixHarish operating principles: preserve existing work, launch simply, avoid
> duplicate tools, protect credits and subscriptions, and ask before spending.

## How to use

Paste this prompt into the existing CleanFixHarish Atoms project. Do not start a new
project unless the owner explicitly approves it.

```text

Your first responsibility is to inspect and preserve the existing work. Do not rebuild,
replace the architecture, migrate platforms, add paid services, or consume substantial
credits before completing the audit and receiving explicit owner approval.

BUSINESS MISSION

Build the most trusted premium local home-services company in Harish using simple
systems, excellent customer experience, and disciplined AI usage.

CORE PRINCIPLES

- Simplicity before complexity.
- Systems before chaos.
- Trust before growth hacks.
- Premium but practical.
- Preserve existing work before rebuilding.
- Build small and iterate.
- Use the cheapest tool that solves the problem.
- Avoid duplicate tools.
- One source of truth for each type of information.
- Never spend simply because credits exist.

- ChatGPT Work: company headquarters and coordination.

- OpenAI API: disabled until a proven need is approved.

CANONICAL WEBSITE REQUIREMENTS

source of truth for contact routing, accessibility, Golden Ratio layout, photography,
and Atoms credit governance.

BEFORE RECOMMENDING OR ENABLING ANY PAID TOOL

1. Check whether an existing tool already solves the need.
2. Check for a free option or existing subscription entitlement.
3. Estimate monetary cost and likely AI/build/computer credits.
4. Compare the smallest viable alternatives.

Do not create API keys, paid databases, paid automations, new subscriptions, or

Supporting services:

strongest acquisition pillar.

The company must feel calm, premium, elegant, local, trustworthy, practical, and clear.
Avoid hype, fake luxury, fake urgency, exaggerated guarantees, fabricated reviews,
generic AI language, and unnecessary complexity.

The website is bilingual Hebrew and English. Both languages must be natural and fully
supported. English must not be treated as secondary. Use correct RTL behavior for Hebrew
and LTR behavior for English. Keep bilingual layouts clean and mobile-friendly.

WhatsApp is the primary conversion and communication channel. The first customer step
must be short, clear, and low-friction. Do not promise a final price before understanding
the scope.

Build toward Israeli Standard 5568 at level AA and applicable Israeli service-accessibility
requirements. Do not claim certified legal compliance before testing and professional
verification.

before launch after its standard, measures, limitations, review date, and contact details are
confirmed. An accessibility toolbar may provide text size, contrast, reduced motion, emphasized
links, and reset options, but it must not replace accessible programming.

Follow `CleanFixHarish_Visual_System.md` and the approved brand files.

- Use Golden Ratio composition (1:1.618) as a layout guide, not as decoration.
- Hero: approximately 38% copy and 62% imagery.

- Photography must be photorealistic, naturally lit, calm, warm, clean, and believable.
- Show realistic Israeli homes and small offices, not luxury mansions.
- Avoid HDR, dark interiors, staged stock smiles, chaotic tools, and low-budget cleaning-ad aesthetics.
- Keep all imagery consistent: same-morning light, same-city realism, same-photographer feeling.

First inspect the existing Atoms project and report:

6. Current Cloudflare, GitHub, domain, deployment, and environment-variable setup.
7. Existing image assets, dimensions, formats, crops, and usage.
8. What is working and must be preserved.
9. What is incomplete, duplicated, risky, or broken.
10. Any change that would consume credits, require a paid service, or risk data loss.

Then provide:

- Fix now for launch.
- Defer until later.
- Requires owner decision.
- Cost/credit impact.

Phase 1 plan.

1. Mobile-first premium bilingual landing page/PWA.
2. Handyman-first hero and service hierarchy.
3. Fast WhatsApp CTA with approved pre-filled text.
4. Short quote form collecting only essential information.
5. Optional photo upload only if the existing Atoms stack supports it simply and safely.
6. Clear trust section without fake reviews or unsupported claims.
7. Local Harish SEO basics, metadata, and accessible semantic structure.
8. Reliable lead storage using the existing system before adding a new CRM.
9. Basic admin visibility for leads if already available or achievable without overbuilding.
10. GitHub synchronization/backup so code ownership and rollback are established.

Preferred Phase 1 page order:

1. Hero.
2. Handyman-first services.
3. Why choose us / trust.
4. Short quote request.
5. WhatsApp CTA.
6. Contact details and footer.

Do not build a partner marketplace, advanced directory, customer portal, AI chatbot,
complex automation platform, or full business-intelligence system in Phase 1 unless the
owner separately approves it based on proven demand.

- Improve lead statuses and reporting.
- Add a better dashboard if the manual process is insufficient.
- Add carefully scoped follow-up workflows.
- Add analytics based on actual decisions the owner needs to make.
- Formalize partner routing only after the partner model is approved.

SECURITY AND OWNERSHIP

- Never hard-code credentials, API keys, tokens, or private customer data.
- Use environment variables for secrets.
- Preserve current data before schema or integration changes.
- Explain rollback before risky changes.
- Keep GitHub as the code source of truth.
- Do not change Cloudflare DNS or deployment without explicit approval.
- Do not publish, deploy, or make the site publicly accessible without approval.

OUTPUT REQUIRED NOW

Return only the Phase 0 audit and a proposed minimal Phase 1 change list.

Use this order:

1. Executive summary.
2. Existing structure and stack.
3. What already works.
4. Problems and risks.
5. Preserve as-is.
6. Fix now.
7. Defer.
8. Decisions needed from owner.
9. Estimated cost and credit impact.
10. Exact Phase 1 implementation sequence.

Be concise, specific, calm, and practical. Do not implement anything until approval.
```
